# 探索方式・Move・温度の選び方

## 最初の分岐

問題を「前から1手ずつ決める」説明が自然で、途中状態から合法な次手を列挙でき、早い段階の選択を後から直しにくいなら構築型です。貪欲、乱択構築、ビームサーチを試します。

完成解を一つ作った後、「一部を変えても有効解を保てる」「変更後の良し悪しを計算できる」なら改善型です。山登り・焼きなましを試します。

両方に見える問題は多くあります。貪欲やビームで初期解を作り、局所探索で改善して構いません。

## 何を最初に選ぶか

- 貪欲: 正の得点を最速で作り、評価とStateの動作を確認する
- 乱択: 手ごとの良い基準が弱いが、作り直しが安い。AHC070のように異なる全体構成を多数試せる
- ビーム: 1手先の評価は有用だが、序盤の1択で後悔しやすい。State cloneのサイズに注意する
- 局所探索: 有効な完成解を少しずつ変えられ、変更の影響を十分速く評価できる

焼きなましが不向きなのではなく、1 Moveごとに後半全体の重い再計算が必要なら、反復回数を稼げないことが問題です。まず全再構築で正しくし、Moveを粗くする、影響範囲を限定する、差分計算を作る、別の構築法へ戻る、の順で考えます。

## Moveの武器

最初は一つだけ実装し、debug検証を通します。

- 1か所変更: 配列、割当、選択値。実装と差分計算が最も簡単
- 2か所交換: 個数制約を保ったまま割当や順序を変える
- 挿入: 順列から一つ抜き、別位置へ入れる
- 区間反転: 経路・順列なら2-optに相当することがある
- 区間移動: まとまりを保ちたい順序問題
- 複数値の同時変更: 1変更では越えられない壁があるとき
- destroy & repair: 一部を壊して貪欲に作り直す

2-optは「訪問順序の区間反転により、主に境界の辺だけが変わる」問題で強い名前です。AHC070のように行動の意味が時系列の状態へ連鎖する問題では、区間反転を入れるだけで安く評価できるとは限りません。名前から採用せず、制約を保つか、影響範囲を限定できるかで決めます。

## 温度の決め方

温度は得点の絶対値ではなく、1 Moveによる典型的な改悪幅の単位です。`10^3` 固定ではありません。

まず、現在解からランダムMoveを数千回試し、採用せず元へ戻しながら負の `delta = next_value - current_value` の絶対値を記録します。中央値、上位10%、最大付近を見ます。

局所探索テンプレートでは次の実行で、標準エラーとlogへ中央値、上位10%、温度候補を出します。

```sh
AHC_SAMPLE_DELTAS=1 AHC_ITERATIONS=10000 ./ahc run 0 --solver local_search_rebuild --debug --no-vis
```

- 開始温度: 典型的な改悪を約50〜80%受け入れる値
- 終了温度: 小さな改悪もほぼ受け入れない値

改悪幅 `d > 0` の受理率を `p` にしたい温度は `T = -d / ln(p)` です。簡単な候補は次です。

```text
start_temperature = median_bad_delta * 2.0
end_temperature   = median_bad_delta * 0.02
```

候補倍率は開始温度を `0.5, 1, 2, 5`、終了温度を `0.005, 0.02, 0.1` 程度で比較します。最初から細かく合わせず、同じseed集合で桁を探ります。

内部評価は必ず「大きいほどよい」にそろえます。公式得点が小さいほどよい場合は符号を反転してからdeltaと温度を考えます。
